# T408 · 5 分钟演示脚本

> 目标：用现有 **12 份 BYD 草稿 + 4 条记录 + 16 个变异**，演示
> **导入 → 解析（含 OCR）→ 审核（规则 + 语义）→ 工作台复核 → 导出** 的完整闭环。
> 只使用现有页面和按钮，不新增功能、不预置演示开关。

## 0. 演示前准备（不占 5 分钟）

### 0.1 环境

- 服务已启动，`/health` 返回 ok；用**复核人/管理员**账号登录（只读账号看不到上传和复核按钮）。
- `P0_TASKS_ENABLED=1`（标准解析走后台任务）；报告批量默认异步，进度会显示“已提交后台审核，等待结果…”。
- 语义审核：`DEEPSEEK_API_KEY` 已配置、`P0_SEMANTIC_ENABLED=1`；“阶段 2”条应显示**语义已运行**。
- 水印清理保持默认开启（不要设置 `P0_WATERMARK_CLEAN=0`）。

### 0.2 样例（测试环境已挂载）

| 用途 | 样例 | 说明 |
|---|---|---|
| 报告审核 | `samples/byd/` 下 12 份 `.docx` | 同一报告编号的 12 个模板变体；6 份 OTS（5 页）、6 份摸底（4 页） |
| 记录校验 | 附录 A 的 4 条记录 | 与 POC 4 条记录同值，编号已替换为 A–D |
| 16 变异 | 附录 B 的 4 个批次 | 均值/日期/判定/重复各 4 条，合计 16 |
| 标准解析（OCR） | `samples/scan-standard.pdf`（示例路径，按测试环境实际挂载替换） | 无文本层的扫描件（44 页，OCR 约 100 秒） |
| 可选水印回归 | 33 页带水印数字版 | 44 项，`5.3.1.1` 保留标准号、0 条“满足中” |

> 33 页带水印样例有可机读文本层，解析时**不会触发 OCR**；要演示 OCR 必须用无文本层的扫描件。
> 如果测试环境只有数字版，把“解析”步骤改为“文本层解析”，并明确说明“本样例 OCR 不触发”，不要假装跑过 OCR。

### 0.3 演示数据

- 把附录 A 存成 `records-clean.json`；用附录 B 的脚本生成 `records-mean.json`、`records-date.json`、`records-judgment.json`、`records-duplicate.json`。
- 5 个 JSON 放在记事本/桌面，演示时直接粘贴；不要现场手改。
- 浏览器开两个标签页：**报告审核**、**标准解析**，方便切换。

### 0.4 5 分钟分配

| 时间 | 内容 | 备注 |
|---|---|---|
| 0:00–0:30 | 导入 12 份报告 + 扫描件 | 不点审核，先起解析 |
| 0:30–1:45 | 解析（OCR）+ 同时提交报告批量审核 | OCR 约 100 秒，等待时做审核 |
| 1:45–2:30 | 看批量/单份结果、规则 + 语义 | 语义未启用则按“未检查”讲 |
| 2:30–3:50 | 工作台复核 + 4 条记录 / 16 变异 | 三种复核状态 + 4 个批次 |
| 3:50–4:30 | 导出批次/单份/标准 Excel | 各下载一次即可 |
| 4:30–5:00 | 收尾结论 + 边界 | 回归基线，不是客户验收 |

## 1. 导入（0:00–0:30）

1. 打开“报告审核”页。
2. 点击“上传检验报告”的虚线框 → 多选 `samples/byd/` 下 **12 份 .docx**。
   - 预期：虚线框显示“12 个文件 · 合计 xx MB”；“开始审核”按钮可用。
   - 先**不要**点“开始审核”。
3. 切到“标准解析”页 → 左侧“上传新标准” → 选择 `samples/scan-standard.pdf`。
   - 预期：显示文件名；“解析标准”按钮可用。
4. 口述：“12 份草稿 + 1 份扫描件已就位；下面先起解析任务，让 OCR 在后台跑。”

## 2. 解析（含 OCR）（0:30–1:45）

1. 在“标准解析”页点“解析标准”。
   - 预期：出现“后台解析任务”框，状态从 **排队中 → 提取 → OCR → 解析 → 保存**，进度条前进；
     下方提示“扫描件会自动启用本地 OCR，耗时约 1–2 分钟”。
2. 立刻切回“报告审核”页，点“开始审核”。
   - 预期：状态“已提交后台审核，等待结果…”。若后台任务串行，审核会排在 OCR 后面；等待时讲数据口径，不要重复点击。
3. 回到“标准解析”页，等任务完成。
   - 预期：标准库出现新标准，显示 **44 页 / 30+ 项**（44 页扫描件实测约 99 秒、32 项、22 项需复核）；
     若有复核标记，条目“状态”列显示“待复核”。
4. 点开该标准。
   - 预期：主表列出条款/实检项目/方法条款/页码/状态；右侧“选择左侧条款开始复核”。
   - 点第一条，预期右侧出现“实检项目 / 技术要求 / 试验方法 / 保存复核”；复核面板可编辑。
5. （可选，10 秒）若改用 33 页带水印数字版：解析结果 **44 项**，`5.3.1.1` 为
   `满足 Q/JLY J7110440E-2021中真空密封性规定的技术要求`，全表 0 条“满足中”；
   解析 warnings 显示“已清洗水印碎片 132 处”。

## 3. 审核（规则 + 语义）（1:45–2:30）

1. 切回“报告审核”页，等批量任务完成。
   - 预期：结果卡“批量审核 · 12 份报告”；KPI 显示 **提交 12 / 已留存 12 / 失败 0**；
     “失败规则”至少 **72**（12 份 × 6 条确定性规则：R01/R02/R03/R04/R09/R10）。
   - 表格 12 行，每行“已审核”，问题汇总能看到“失败 6 / 通过 5”这一量级；若语义/部分规则另有发现，数字会更多。
2. 点第一行的“查看”。
   - 预期：单份结果顶部显示“失败 6 / 通过 5 / 未检查 x”的汇总，“阶段 2”条显示
     **部分规则 / 规则 DSL / 语义已运行（绿色）**。
   - 向下滚动：每条问题都有 `规则 / 结论 / 定位（页-段-单元格）/ 证据 / 建议`。
   - 语义发现的问题会带“语义”层标签；若显示“未启用”，说明 key 未生效——按预案跳过，**不当作通过**。
3. 口述：“规则层给确定性问题，语义层给表述/名称/结论类问题；两层各自出问题，缺数据只标未检查、不当作通过。”

## 4. 工作台复核（2:30–3:50）

1. 在单份结果里，对 3 条问题分别点 **采纳 / 忽略 / 误报**。
   - 预期：每条状态立即变为“已采纳/已忽略/误报”；顶部“复核 x/y”计数增加；
     刷新或从“审核历史”重新打开，状态仍在（留痕）。
2. 口述：“验收要求每条问题都有人工状态；这里演示三种状态和留痕，实际验收逐条点完。”
3. 回到“报告审核”页，展开下方“批量记录校验”。
4. 清空文本框，粘贴 `records-clean.json`，点“校验记录”。
   - 预期：绿色提示“4 条记录全部通过均值、日期、判定与编号唯一性检查”。
5. 依次粘贴 4 个变异批次，每次点“校验记录”：
   - `records-mean.json` → **4 项问题**，规则 `REC-01`（复核均值与计算不一致）。
   - `records-date.json` → **4 项问题**，规则 `REC-02`（评价日期早于试验日期）。
   - `records-judgment.json` → **4 项问题**，规则 `REC-03`（判定与均值/限值不一致）。
   - `records-duplicate.json` → **4 项问题**，规则 `REC-04`（样品编号重复）。
   - 合计 **16/16 变异检出**，干净 4 条 0 误报。
6. 若时间不够：只跑 clean + mean + duplicate 三批（0 + 4 + 4），口述另外 8 条已备好、回归 16/16。

## 5. 导出（3:50–4:30）

1. 在批量结果卡点“导出汇总 Excel”。
   - 预期：下载 `报告批量审核-<batch_id>.xlsx`；打开含“批次汇总 + 逐份问题清单”。
2. 在单份结果卡点“导出 Excel”。
   - 预期：下载单份审核 Excel，含“审核汇总 + 问题清单”（规则、结论、定位、证据、建议）。
3. 在“标准解析”详情页点“导出 Excel”。
   - 预期：下载标准 Excel，行数与解析条目一致（44 页扫描件为 32 行；33 页数字版为 44 行），
     含条款/实检项目/技术要求/试验方法/页码/复核状态。
4. 口述：“导出的是可复核的记录，不是截图；原始报告和标准只留在受控目录。”

## 6. 收尾（4:30–5:00）

一句话总结：

> 12 份草稿 12/12 复现 6 类确定性缺陷；4 条记录 0 误报，16 个变异 16/16 检出；
> 扫描件走完 OCR 解析与人工复核；报告审核叠加规则 + 语义；问题可复核留痕、结果可导出。

必须补一句边界：

> 这是**回归基线**，不是客户验收；20–30 份正式报告（D3）和金标准到位后，才能按阶段 3 门禁算准确率/召回并签字。

## 附录 B · 16 变异批次生成

演示前在 `p0/` 目录执行一次，生成 4 个 JSON：

```bash
python - <<'PY'
import json
from datetime import date, timedelta

records = [
    {"sample_no":"A","limit":3.5,"scores":[3.5,4.0,4.0],"reported_mean":3.8,"test_date":"2026-01-08","eval_date":"2026-01-08","judgment":"不符合"},
    {"sample_no":"B","limit":3.5,"scores":[3.5,3.5,4.0],"reported_mean":3.7,"test_date":"2026-01-08","eval_date":"2026-01-08","judgment":"不符合"},
    {"sample_no":"C","limit":3.5,"scores":[4.0,4.0,4.5],"reported_mean":4.2,"test_date":"2026-01-05","eval_date":"2026-01-05","judgment":"不符合"},
    {"sample_no":"D","limit":3.3,"scores":[3.5,4.0,4.0],"reported_mean":3.8,"test_date":"2026-01-05","eval_date":"2026-01-05","judgment":"不符合"},
]
def dump(name, rows):
    open(f"/tmp/{name}.json", "w", encoding="utf-8").write(
        json.dumps({"records": rows}, ensure_ascii=False, indent=2)
    )
dump("records-clean", records)
dump("records-mean", [{**r, "reported_mean": round(r["reported_mean"] + 0.1, 1)} for r in records])
dump("records-date", [{**r, "eval_date": (date.fromisoformat(r["test_date"]) - timedelta(days=1)).isoformat()} for r in records])
dump("records-judgment", [{**r, "judgment": "符合" if r["judgment"] != "符合" else "不符合"} for r in records])
dump("records-duplicate", records + [dict(r) for r in records])
PY
```

预期：clean 0；mean/date/judgment/duplicate 各 4 项，合计 16/16。

## 附录 D · 常见卡点

- **语义显示“未启用”**：检查 `DEEPSEEK_API_KEY`、`P0_SEMANTIC_ENABLED=1`，重启服务；未启用时按“未检查”讲，不能说通过。
- **解析任务一直排队**：确认 `P0_TASKS_ENABLED=1`；若后台 worker 只有 1 个，报告批量会排在 OCR 后，等任务完成再继续。
- **批量上传按钮不可用**：账号不是复核人/管理员；只读账号看不到上传/复核/导出。
- **OCR 超过 2 分钟**：44 页扫描件约 99 秒；机器负载高时会变慢。演示前先跑一次预热，或改用页数更少的扫描件。
- **水印样例没触发 OCR**：数字版有文本层，本来就不会 OCR；换成无文本层扫描件，别把“文本层解析”说成 OCR。
