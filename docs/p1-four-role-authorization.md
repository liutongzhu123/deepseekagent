# 中汽四角色授权实施约定

状态：代码实现完成，联调/部署验收中（服务端四角色矩阵、账号级审核例外、CRM 项目价格写入隔离及 WeKnora 显式 OIDC 身份绑定已合并；CNZ WeKnora 独立栈和精简后的知识库前端已部署在 testkb。浏览器确认登录页可用，但因没有测试管理员账号，登录后导航与操作仍未做浏览器验收。历史账号仍须逐人确认；客户 IdP、管理员开户、合成资料检索、业务工作台联跳和恢复演练未验收）。角色名称和业务职责以客户 2026-11-24 提供的客服需求表为准；P0 历史角色只作迁移来源，不作为第五类角色。

## 1. 四个角色

| 项目角色 | 内部代码 | 默认职责边界 |
|---|---|---|
| 新客户/小微客户 | `customer` | 只通过小程序身份使用本人企业的咨询、报价和委托接口；不创建 P0 员工账号，不能进入员工工作台或 WeKnora 管理端 |
| 业务经理 | `business_manager` | AI 报价辅助、委托审核、单笔报价/折扣调整、客户沟通、所属客户及咨询记录、主动会话、获批项目内的 CRM 报价数据维护 |
| 系统管理员 | `admin` | 知识库、排期/资质库、项目名称映射、黑白名单、中介风险、系统规则、统计、账号和运行配置；负责客户注册审核 |
| 技术部门 | `technical` | 排期项目库调整、加急规则制定/维护、业务规则读取和技术支持；不因技术身份自动获得报价/CRM、客户资料、报告审核、标准复核或全库管理 |

项目、客户、部门和知识范围是数据授权，不增加角色。业务经理的单笔折扣调整与系统管理员的全局折扣规则维护是两种权限。

CRM 价格维护按账号的项目授权执行：新增、修改或删除时必须同时提供匹配 CRM 项目表的项目编号和名称；无权项目、未知项目及编号/名称冲突均拒绝。业务经理客服队列也按项目范围过滤。客户注册审核只授予系统管理员，委托审核和客户沟通由业务经理负责。技术人员可读取业务规则并维护排期/加急规则，不能据此访问标准解析或报价操作。

## 2. 历史账号和逐人权限

旧角色 `admin` 可迁为 `admin`，旧 `sales` 可建议映射为 `business_manager`；实际迁移仍须回读账号清单。旧 `reviewer`、`viewer` 不自动归入任何角色。逐账号确认新角色和项目/客户范围后才启用。

用户已确认：原 reviewer 的报告审核、标准复核权限逐账号确认，四角色名称不变。实现上用账号级、带审批人/时间/原因的权限授权保存这些特例；它不是新的角色。未获逐人批准的账号不能调用对应审核接口。角色或组织归属发生变化时，历史审核授权先撤销，再由管理员按新岗位重新确认。

不得因邮箱相同、首次 OIDC 登录、导入旧账号或前端隐藏按钮而自动获得权限。邮箱仅作核对；P0 OIDC 回调现按已绑定的 `(issuer, subject)` 查找账号，缺少绑定或发生重复绑定均拒绝登录。管理员通过 `PUT/DELETE /api/v1/auth/users/{username}/oidc-identity` 手工维护绑定，变更先记审计；PostgreSQL 增加唯一身份表约束，不复用邮箱作为主键。

## 3. 失效场景与处理要求

| 编号 | 失效场景 | 必须行为 |
|---|---|---|
| F1 | 账号仍是未知/旧角色，或迁移映射缺失 | 拒绝登录或业务请求；不猜测映射、不回退为管理员 |
| F2 | 外部客户尝试员工 P0 工作台或 WeKnora 管理端 | 拒绝；只开放独立的小程序业务凭证及本人数据 API |
| F3 | reviewer 账号的例外审核权没有逐人批准、原因或审批人 | 拒绝报告审核/标准复核；不因为旧角色名称放行 |
| F4 | 前端隐藏了入口，但用户直接请求 API | 服务端权限检查仍拒绝，并记录拒绝审计 |
| F5 | 业务经理把单笔折扣当作全局规则维护 | 只允许单笔报价动作；全局折扣规则写入必须由系统管理员执行 |
| F6 | 技术人员尝试调整报价、客户或资质全局数据 | 拒绝；其排期/加急权限不扩展为 CRM/资质全库权限 |
| F7 | 业务经理获 CRM 报价维护权后试图修改其他基础资料或越权项目价格 | 报价写权限与 CRM 全库维护分开；价格写入须通过 CRM 项目编号/名称双重匹配及账号项目授权 |
| F8 | 角色降级、停用或所属项目变更后旧授权残留 | 撤销旧会话并清理/冻结旧例外授权；范围变化需重新审批 |
| F9 | 权限审计存储失败 | 不保存新的授权、不返回成功；避免“操作成功但没有授权证据” |

## 4. 实施顺序

1. 从代码枚举所有权限消费者，按默认角色职责建立后端权限矩阵；管理界面仅作为展示，不作授权依据。
2. 已增加 `PUT /api/v1/auth/users/{username}/review-permissions`：仅有用户管理权限的管理员可逐账号替换 `report:read`、`report:audit`、`standard:review` 授权；每项保存审批人、时间、原因。管理员不能给自己授予审核例外。审计写入失败时 API 返回 503，账号授权不保存。界面要求选择权限并填写原因。
3. 为历史账号提供只读迁移预览，输出账号标识、旧角色、待确认的新角色/项目范围；确认文件不进入仓库。应用映射前先备份账号库，并提供可逆导出。
4. 新账号只允许四个项目角色；迁移未确认账号拒绝访问。客户小程序身份与员工密码/OIDC 账户分离。
5. P0 与 WeKnora 分别校验身份和授权。P0 服务账号只能访问项目授权的知识范围；浏览器和小程序不持有管理员 API key。

报告审核/标准复核的逐账号名单、经理客户归属、技术部门项目范围、客户 IdP 配置均未从 testkb 或其他生产账号库读取。获得对应授权清单前，只能实现并验证迁移工具和模拟账号，不能替客户映射真实账号。
