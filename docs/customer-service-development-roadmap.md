# 中汽零部件智能客服项目：目标模式开发路线

**目标：** 完成客户方案对应的智能客服与报价范围（`CS-1` 至 `CS-8`，共 29 项需求）的可交付实现；在客户输入缺失时先完成隔离的本地模拟、接口契约、失败降级和管理工作台。任何模拟实现都不得标记为真实系统集成或客户验收。

**执行模式：** 本路线由 Codex 作为持续目标推进。每轮先确认权威源码和当前 Git 状态，再完成一个能独立审查的任务，更新路线状态和下一个任务。依照仓库规范，每个任务单独分支、PR 以 `main` 为 base；禁止把 IDE 本地配置或客户原始资料放进共享源码。

**需求基线：** 客户提供的《AI智能客服系统建设方案-V3.docx》（正文版本标注 V2.0，2026 年 7 月）、`docs/requirements.yaml`、`docs/BACKLOG.yaml`、`docs/p1-plan.md`、`p0/docs/customer-service-v3-plan.md`。如果客户后续确认的版本与仓库清单不一致，以客户确认版本为准并记录变更。

## 1. 范围与完成定义

### 本目标覆盖

覆盖智能客服与报价需求 `CS-1.1` 至 `CS-8.4`：基础数据、客户身份、报价、AI 辅助报价、自助委托、业务工作台、规则配置和四类外部对接。现有报告审核、标准解析作为可复用底座，不把其独立的 `RA`、`SP` backlog 混入本路线。

### 两种完成状态分别记录

1. **可开发任务完成：** 在本地或隔离演示环境中实现确定的流程、数据模型、权限、审计、适配器接口、模拟器、错误降级及可复现验收材料。合成数据清楚标识；外部接口使用明确的模拟/契约适配器。
2. **生产集成完成：** 只有在客户提供接口文档、账号、网络策略、数据授权、规则签字、合规确认及验收样本后，完成真实端到端集成并通过客户 UAT，才能标记完成。缺少前置输入时列为外部阻塞，不伪造“已完成”。

本目标不承诺客户何时提供资料或外部审批何时通过。只要仍有可独立开发的工作，就继续推进；若只剩外部阻塞，保持目标进行中并列明恢复条件。

## 3. 开发阶段与验收门

阶段顺序按依赖推进，不给虚假工期。每个阶段可以拆成多个单任务 PR；只有当前任务验收后才开始依赖它的下一项。

### G0：工作树收敛与 S1 内部报价事实预览

**需求：** `CS-1.1`、`CS-1.3`、`CS-1.4`、`CS-3.2`、`CS-3.4`、`CS-4.1`、`CS-4.2`。

**开发项：** 完成当前分支改动审查；内部 CRM 预览展示候选差异、来源版本和解析证据；失败时无合成回退；确认币种、税、数量、资质、未审映射等未知项都要求人工复核；清理文档与 Schema 的接口差异。

**验收门：** 合成数据与 CRM 来源无法混淆；同一询价行可追溯到来源版本/唯一记录编号；重复候选不自动选价；项目级权限在读取 CRM 前执行且不暴露其他项目的资质统计；演示价格覆盖当前日期并保留过期分支；不计算总价、折扣或阈值；不生成客户报价、不写回 CRM；`off`、API 预留、读取异常均明确降级。

### G1：CS-1 数据治理与离线数据维护

**需求：** `CS-1.1` 至 `CS-1.4`。

**开发项：** `CS_CRM_SCOPE` 与 `CS_BASE_GOV` 已完成本地实现：CRM 列表/编号查询/报价对账按授权项目隔离；本地库冲突需显式覆盖、导入逐行报告、变更版本审计/回滚、映射审批生效、过期价格/资质不参与当前查询。管理员工作台覆盖价格、排期、资质和项目名称映射维护；写操作要求来源/原因，重复键显式覆盖。名称映射新建/更改默认待审批，批准要求单独确认和依据。价格页不计算对客报价，也不推断币种/税率；资质页不代替客户认可/真实性核验。排期候选解析仅为浏览器内确定性合成演示，显示原文和行号，人工确认后才允许提交，不声称 AI 识别。CRM API、客户认可清单解析与排期业务语义仍等待客户资料；后续获得字段和样表后再完善真实适配及人工复核工作流。

**验收门：** 失效/冲突数据不能覆盖有效数据；未审映射不能改变匹配结果；资质只到项目级时不输出标准级结论；排期未确认不推断交期；每次维护可审计、可回滚。接客户 CRM/认可清单前，所有本地模拟适配均明确标示。

### G2：身份、注册与风险处置模拟闭环

**需求：** `CS-2.1` 至 `CS-2.6`。

**开发项：** 注册演示 API、opt-in 小程序客户端和管理员审核页面已完成；审核队列新增本地黑/白名单及中介关键词候选提示，审核提交精确绑定规则版本和登记资料修订号，版本过期则拒绝并要求刷新，始终要求人工决定。登记创建要求 `Idempotency-Key`：小程序在发送前持久化随机操作号和原表单，服务端按操作号摘要与规范化内容摘要去重，同键异文冲突；同键重试可恢复相同演示登记凭证。创建响应不确定时页面恢复原表单，必须沿用原请求确认结果；清除该待确认编号前会先展示提示。已有登记凭证提交前先刷新服务端状态，以恢复提交响应丢失后的重试。本人查询不返回内部风险候选。该能力不调用企查查，也不代表真实身份或企业核验。真实核验、客户签署的名单语义和业务经理地域映射须在客户规则与接口到位后接入。

**登记更新重试边界已补齐：** 修改草稿/待补件登记也要求 `Idempotency-Key`；客户端先保存待确认编号和原表单，服务端按登记凭证作用域、操作号与规范化资料摘要回放，异文冲突。每条登记最多保留 100 次更新操作摘要；审核状态发生变化后旧操作只返回当前登记，不重复增加修订/历史。待处理操作属于其他登记凭证时，小程序隐藏其资料并阻止继续提交。`p0/tests/test_customer_registration.py` 和 `p0/miniprogram/tests/registration-api.test.js` 覆盖响应丢失、同键重试和跨账号隔离。

**管理审核响应恢复已补齐：** 登记和委托的管理审核均要求 `Idempotency-Key`，服务端按审核人、目标记录、操作号和载荷摘要去重。同键同载荷重试返回当前状态，不重复增加审核历史；同键不同内容返回冲突；后续补件/重审后重放旧 key 只读取当前状态，不回滚较新的决定。登记审核摘要上限为 100，达到上限后仍可恢复历史操作但拒绝新 key。管理台在提交前将原决定、原因和 key 存入当前浏览器会话，网络或服务端结果不确定时显示“恢复上次审核”，并在恢复成功后清除待办。对应 API 回归在 `p0/tests/test_customer_registration.py`、`p0/tests/test_customer_order_flow.py`，工作台脚本语法检查为 `node --check p0/static/ui.js`。

**审核竞争边界已补齐：** 委托创建时 revision 为 1，客户补件、管理员审核和客户确认均在文件锁内递增。审核请求包含管理员从队列读到的 revision；如客户在点击后先补件，服务端在锁内拒绝旧 revision，避免把经理没看过的新内容批准。登记审核则在取得规则快照前持有与配置写入相同的跨进程 sidecar 锁，并保持到审核记录写入，避免其他 worker 在规则检查与决定落盘之间更换规则。管理台按状态筛选时仍保留会话中有待恢复请求的记录；本地待恢复登记还会校验保存的载荷指纹。`

**名单管理本地门已补齐：** 管理员可以直接编辑增删黑名单，并以 UTF-8 单列 CSV 合并或明确替换导入、导出。名单写入与业务配置重置绑定配置 revision，并在写入前要求操作审计；配置损坏、过期 revision 或审计不可用均拒绝写入。导入严格校验大小/行列，导出对电子表格公式前缀加转义。销售等非管理员不能通过配置、草稿或规则预览读取或探测黑白名单。名单来源、正式处置语义和留存仍待客户确认。

**验收门：** 游客/未审批/审批中/通过/拒绝状态均有明确行为；身份或企业信息不完整、名单冲突、外部服务不可用均转人工；客户不得看到内部黑白名单命中原因；多客户数据隔离；模拟数据不出现在生产列表。

**外部门：** 真实微信登录/手机号、企查查、客户主体核验与地理经理映射，依赖小程序主体/AppID、API 账号、字段、授权和策略确认。

### G3：内部报价流程与人工接手

**需求：** `CS-3.1` 至 `CS-3.6`。

**开发项：** 将信息收集、解析结果编辑、价格/排期/资质状态、补问、转人工、上下文传递和经理接单串为后端状态流；消费已批准且有版本的规则配置；做规则快照和可重放决策记录。已补询价创建幂等恢复：页面发起前保存安全随机操作号和原内容，服务端按操作者/操作号/规范化内容摘要去重；同键重试回读原工单，同键异文冲突，并发同键只创建一条；工单后续状态变化不会再建单；敏感摘要不会返回 API。管理员接单/转交/关闭也要求稳定操作号；响应不确定时管理台保留原动作和载荷，可恢复重试，筛选状态不会隐藏待恢复项目。服务端对同键同载荷回放当前工单、异文冲突且不重复追加历史，最多留 100 条摘要，损坏或超限 fail closed。提交重试先回读服务端状态，客服回复和询价创建均在安全随机数不可用时 fail closed。用户点击新建时，待确认工单会先沿用原操作号回放，已确认待办可清理；数值数量须有限、为正且小于 10^40；来源行号和置信度也有限值，防止任意 JSON 输入污染本地存储。

**验收门：** 缺字段、低置信、无标准、价格过期/冲突、未知资质、CRM 不可用、高价、重点客户和客户要求人工都有明确路径；规则没有业务签字时只给内部解释且不自动出价；金额边界（`<10000`/`≥10000`）、税、折扣顺序、加急费未确认时按人工处理；任何转人工都保留授权范围内上下文。

| `needs_human` | 客户可修改回到 `draft`；重新提交前重新验证 CRM | 修改后回到 `draft` | 可接单/转交 | 可带原因关闭 |
| `resolved` | 终态 | 禁止 | 禁止 | 重复关闭冲突 |

**G3 本地失败路径：** F1 无项目权限时先于 CRM 和文件写入拒绝；F2 CRM 功能关闭、模式不符、映射冲突或来源离线时保留上下文并转人工，不回退合成价；F3 重复提交/非法状态转移返回冲突；F4 工单仅创建人、受派人或管理员可读；F5 非管理员不能操作演示队列；F6 已被他人接单时不能覆盖；F7 空原因、无效转派账号或未授权项目不能变更记录；F8 文件损坏或写入失败不报告成功；F9 创建已落库但响应丢失时同一操作者/操作号/内容只回放原工单，即使其状态已变化；F10 同一操作号配不同内容返回冲突；F11 重复或损坏的私有幂等元数据 fail closed；F12 来源行号不是 1 至 1000000 的整数、置信度不是有限数值或超出 0 至 1 时拒绝写入；F13 浏览器不能取得安全随机数或无法持久化待重试内容时，创建/回复不发请求；F14 数值数量不是小于 10^40 的有限正数时拒绝写入，防止损坏 JSON 存储；F15 管理员接单/转交/关闭要求稳定操作号，同键同载荷回放当前状态、同键异文冲突，最多 100 条摘要，损坏或超限元数据 fail closed。状态审计按动作记录前后状态、操作者、原因与时间。当前队列只授予管理员，待客户给出业务经理角色/授权映射后再开放给经理。

### G4：AI 辅助报价与 CRM 草稿

**需求：** `CS-4.1`、`CS-4.2`（与 G0、G3 衔接）。

**开发项：** 统一 Word 表格/Excel/PDF/图片解析结果为可编辑需求行；补齐样品、标准/条款、项目、数量/单位与行级证据；提供内部预览和 CRM 格式草稿导出。当前 DOCX 支持单个可解析询价表；多询价表、超限或压缩体积异常的文件明确拒绝，要求拆分后上传。

**验收门：** 原文件价格不覆盖 CRM 权威价；解析结果可编辑且保留来源行/置信度；解析→复核令牌绑定操作者、项目、规范化文件名、文件 SHA-256 和报价规则配置，价格预览与候选复核只接受完全匹配的审计明细；缺失/歧义项显式留空并注明待补；导出不触发 CRM 写入。原 `/quotes/parse` 响应包含上传文件自身的字段（可能含单价），新复核/只读预览响应不回传单价。真实样本准确率只能以客户金标准统计，合成数据不能作为客户验收数字。

**本地子项 `CS_AIQUOTE_SIM` 已实现：** DOCX 表格解析、四种输入类型的复核与失败回归、前后值审计、服务端 HMAC 短时解析凭证、仅凭已复核行查询价格、客户端迟到响应保护。DOCX 多张可解析表格、超过 300 行扫描/200 行复核限制或高解压体积均显式拒绝，避免静默遗漏或资源膨胀。客户资料、字段映射和准确率验收仍待客户提供金标准。
