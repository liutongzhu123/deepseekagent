## 5. 发现与修复

1. **修复（本 PR）**：`p0/eval/stage3_acceptance.py` 原先在逐份记录中跳过 `case_kind=synthetic`，
   JSON 也不含逐份结果，导致 T302 无法核对「每份草稿 fail 集合」。现改为：
   - JSON 增加 `outcomes[]`（data_id、期望/实际 fail、集合一致、模板、耗时、缺口）；
   - 逐份记录包含演练行，新增「计入验收」列，演练行单份结论显示「演练」；
   - blocked 文案注明演练样本数；新增 2 条单测。
2. **记录（不改设计）**：stage1 基线只有 R01–R11，T301 是全层（stage2=True）集合；T302 对比时取 R 子集，
   D3 正式验收清单写全层期望。
3. **记录**：4 条记录 + 16 变异不属于 T301（T301 只审报告），由 `eval.stage1_regression` 单独跑；
   T302 的「完整链路」因此是两条命令，本报告都已实际执行。
4. **未修复（环境/数据）**：真实 12 份草稿、4 条记录 xlsx、POC 标注未挂载；这是 T302 真实验收的唯一阻塞，
   不是代码问题。样例目录、文件清单和脱敏口径见 `docs/stage3-acceptance/README.md` §2。
