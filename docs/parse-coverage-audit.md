# 解析覆盖率审计（2026-11-07）

样本：`/opt/dsh-agent/samples/standards/` 下 4 份 + `/opt/dsh-agent/samples/watermark-sample.pdf`
（EPB 制动钳，33 页）。均标秘密级、不入库；本文件只记录页数、字符数、表格数、条款数等
结构信息，不记录客户标准的条款正文、项目名称或限值。

## 一句话结论

**按原始文本层字符计，解析只读到了标准的 5.8%–11.8%（4 份有文本层的样本合计 8.2%）。
最关键的漏抽不是切分，而是表格：103 张 ≥150 字的大表共 66,700 字，只有 2 张的表内文字
过半进入 items，0 张走 pdfplumber 结构化表格路径。**

## 口径与复现

- **原始文本字符**：`pypdf` 逐页 `extract_text()` 之和（未去水印）。
- **抽出字符**：items 的 `requirement` + `method` 字符数之和（当前唯一进入条款的两个字段）。
- **覆盖率** = 抽出字符 / 原始文本字符。
- **表格**：`pdfplumber.extract_tables()`；“大表”指单元格总字符 ≥150，用来区分符号/图例表与
  真正承载限值、试验条件、检验项目的表。**表内文字覆盖**指表内文字的 6-gram 有多少出现在
  items 文本里；页级覆盖同理。

```bash
cd p0
python3 scripts/audit_parse_coverage.py \
  --samples /opt/dsh-agent/samples/standards /opt/dsh-agent/samples/watermark-sample.pdf
```

脚本只输出聚合数字，不输出条款文本。

## 逐份结论

### A · EPB 制动钳（33 页）
- 8 张表，7 张是大表（4,449 字），表头是「试验项目/技术要求/试验方法/出厂检验」的检验表；
  表内文字只有 4.5% 进入 items，0 张结构化解析。items 的 `item-table` 来源只用了表里的
  条款号映射，限值列没进来。
- 水印清洗移除 7,095 字（原始字符的 11%），是本批唯一有明显水印文本层的样本。
- 13/33 页页级覆盖 <10%，集中在封面、目录、前言和表格页；重复页眉/表头 660 字。
- 多栏：未发现（沿用上一轮诊断矩阵的逐份检查）。

### B · 安全气囊 ECU（12 页）
- 29 条 items 全部是 `method-only`，`requirement` 字段为空——真正的检验项目和要求在表 4
  型式检验表里，2 张大表（466 字）表内文字 0% 进入 items，0 张结构化解析。
- 原始 11,424 字只抽出 1,353 字（11.8%）；4/12 页页级覆盖 <10%。
- 结论：这份标准的丢失点不是“抽不准”，而是“没看表”；需求侧目前等于没抽。

### C · 电磁兼容 EMC（57 页）
- 33 张表，32 张大表（15,698 字），表内文字只进 10.1%；只有 2 张过半，0 张结构化解析。
- 附录 A–D 共 13 页 / 15,376 字，items 0 条锚定在附录——附录完全没扫。
- 12 条 items 只覆盖各检测章的 `x.1 技术要求` + `x.2 试验方法` 两段；选择矩阵、限值表和
  波形参数没有进入 items。23/57 页页级覆盖 <10%。

### D · 电气电子通用（137 页）
- 78 张表，62 张大表（46,087 字），表内文字只进 5.0%，0 张结构化解析；这是 5 份里表格
  体量最大的一份（表格字符占原始文本 20%）。
- 51 条 items 只覆盖 `5.x.y.z` 的正文；表格、图示和大量试验参数留在 items 之外。
- 重复页眉/表头 14,385 字；67/137 页页级覆盖 <10%。总覆盖率 5.8%，是 4 份里最低。
- 多栏：未发现。

### E · 扫描件（2 页）
- 无文本层（0 字），文本覆盖率不适用；生产链路会走 OCR。
- 内容仍是检测报价单而非标准（沿用上一轮诊断结论），本轮不做 OCR 复测。
- 建议换一份真实扫描标准再测，当前样本不能代表扫描标准覆盖率。

## 四个丢失环节的判定

| 环节 | 判定 | 证据 |
|---|---|---|
| 表格没解析 | **主因** | 103 张大表 / 66,700 字，仅 2 张过半进入 items，0 张结构化 |
| 附录没扫 | 局部 | EMC 附录 13 页 / 15,376 字，0 条 items 锚定 |
| 页眉页脚/水印 | 次要 | EPB 水印 7,095 字（11%）；4 份重复页眉/表头合计 22,567 字 |
| 多栏排版 | 未发现 | 本批 5 份按单栏文本层输出，未出现跨栏交错 |

剩余部分是封面、目录、前言、图示、参考文献和纯数值/英文行。解析器的 `_body_lines` 只保留
含中文的行，纯数值、单位和英文行会被过滤，这也是限值与试验条件丢失的一条路径。

## 对 B1/B2/B4 的影响

- **B1 条件 / B2 限值**：限值和试验条件大多在表格里；表格文字只有约 6% 进入 items，
  这两项的命中率会被系统性低估，不是识别算法差。
- **B4 公式**：公式行往往含数字/符号、中文很少，`_body_lines` 会把它们过滤掉；真实样例
  里 0 条公式可能同时有“确实没有”和“被过滤”两种原因，需要表格/数值行解析后才能分清。
- **条款数量**：items 数（44/29/12/51）只是“进了 requirement+method 的条款数”，不能当作
  标准里的项目总数。

## 本轮不做

按“先只做测量”：不改解析器、不加表格解析、不扫附录。下一步优先级建议：
1. 表格结构化（先做检验项目表/限值表）；
2. 附录扫描；
3. 纯数值/英文行的保留策略（影响公式与限值）。

## T1 后覆盖率（表格结构化，2026-11-07）

上一节写于 T1 之前；T1 已按“先做表格结构化”的优先级落地。T1 只新增顶层 `tables[]`，
不改 items 的 `requirement`/`method`，也不改 B1–B4。items 口径仍是 8.2%；把 `tables[]`
的单元格文字与 items 一起计入后，同口径结果为 **25.2%**。

### 口径

- 条目：`{clause, clause_source, header[], rows[[...]], page, raw_bbox,
  header_detected, merged_cells, has_merges, parse_warning}`；表内文字不进入
  `requirement`。
- 大表：沿用上一节，pdfplumber 单表单元格总字符 ≥150。
- 结构化：大表按 page + bbox 与 `tables[]` 条目一一匹配。
- 表头识别：`header_detected` 为真表示抽到列名行；不表示列语义已经映射（T2 才做）。
- 覆盖率（字符口径）：（items 的 requirement+method 字符 + tables[] 表头/单元格字符）
  / 原始文本字符。6-gram 口径按去重后的文本片段覆盖，作为交叉校验。

- 6-gram 口径（items → items+tables）：A 18.8→27.0、B 11.6→15.1、C 14.8→25.1、
  D 9.4→25.8；与字符口径同向。
- 共 122 条 `tables[]`（含 <150 字小表）；38 条带 `parse_warning`（表头缺失、水印残留
  或条款按邻近条目推断）。
- 人工复核 96 张识别到表头的大表：94 张列名为真实列名（部分单元格带水印碎片，列位
  正确）；2 张续页表（EPB 第 30/31 页）的表头混入数据行和水印，已标 `parse_warning`；
  其余 7 张大表确认无表头（图/数据表），按无表头导出，未强行套表头。
- 条款归属：122 条全部有 `clause`；主路径是表上方最近的条款标题（含 A/B/C 附录号），
  4 张通用标准的表按邻近条目回退（`clause_source=item-page`）。少量跨页表只能定位到
  上级条款（如 `5.2.1`），没有强行猜末级条款。

### 限制与未做

1. 跨页表按页拆成多条，不合并；续页没有重复表头时，可能按无表头或噪声表头导出
   （EPB 第 30/31 页已标 warning）。
2. 水印文字会残留在部分单元格；含日期/邮箱等明显页眉残留的表头已加 `parse_warning`，
   但表内值仍需人工复核。
3. pdfplumber 只抽有框线/网格的表；无框线表、图内文字和扫描件（无文本层）不在本次
   能力内。图内文字偶尔被识别成多列伪表格，会按无表头/警告导出。
4. 未做 T2：`header[]` 是原始列名，限值/条件列没有映射到 `limits[]`/`conditions[]`，
   也没有改写 `requirement`。
5. 表内文字没有进入 items，所以上一节的 `table_coverage`（表内文字进 items 的比例）
   仍是 5%–10%；T1 的价值体现在 `tables[]` 的独立覆盖率（25.2%）。
