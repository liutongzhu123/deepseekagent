## 2. 下一步目标与排序原则

**目标**：把 0.6.0 推到“内部多用户可日常试用”的 P1 内测版。每个增量都要可演示、可回滚、可验证，
不以“页面能点开”或“接口 200”作为完成。

**排序原则**：

1. 先上线、先可回滚，再动数据；
2. 先补生产化底座（数据层、异步、备份），再补业务体验；
3. 依赖客户接口的工作先做 Excel/CSV 适配层，接口到位后替换，不空等；
4. 每个增量独立验收，不把多个大改动捆在一个 PR 里；
5. 演示体验不单列阶段：进度/错误提示随 P1-1、P1-2 交付，真实样例与 UAT 放在 P1-4。

## 4. 近期三个增量的定义

### P1-0 发布 0.6.0（先做，低风险）

1. 打包 `p0/app`、`p0/static`、`p0/tests`、`requirements.txt`，保留上一版回滚包；
2. 服务器 `pytest -q` → `systemctl restart cq-p0-api` → `/health` 确认 0.6.0；
3. 管理员登录，依次验证五个页签、四角色权限（viewer 越权 403）、审计查询/导出、四条业务链路；
4. 用 1 份标准 + 1 份报告 + 1 个 DVP 做冒烟；记录回滚命令。

**完成标准**：生产 `/health`=0.6.0；上述检查全过；失败可在 10 分钟内回退 0.5.0。
**不做**：不在这一步改数据结构、不迁移历史数据。

### P1-1 数据层（PostgreSQL + MinIO）

**范围（本轮切片）**：

- 表：`users`、`projects` / `project_members`、`standards`、`standard_versions`、`standard_items`、
  `quotes`、`quote_items`、`audit_events`、`tasks`、`files`；
- 解析结果用 JSONB 保存，保留 `version` 与修订链；文件元数据存 `files`，原件/导出进 MinIO；
- 迁移：一次性脚本从 `data/auth/users.json`、`data/standards/*/result.json`、`data/quotes/*`、
  `data/audit/audit.jsonl` 导入；对账（数量、ID、哈希、抽样字段）；
- 兼容：`P0_STORE=json|postgres` 开关；迁移期双读；回滚脚本回到文件模式；
- 备份：每日 `pg_dump` + MinIO 镜像到独立存储；做一次恢复演练。

**完成标准**：迁移对账 0 差异；现有 API 路径/字段不变；pytest 全绿；审计查询不再全量扫文件；
回滚演练可在 30 分钟内恢复文件模式。
**不做**：不把报告审核历史、CRM 实体一次性建全；不换前端。

### P1-2 异步任务（OCR / 解析 / 发布）

**范围**：

- 新增任务表与独立 worker（systemd 单服务，先不引入新 Redis 依赖），任务状态
  `queued/running/succeeded/failed/cancelled`；
- `POST /api/v1/standards/parse` 大文件/扫描件返回 `202 + task_id`；新增
  `GET /api/v1/tasks/{id}`（进度、阶段、错误）；小文本层 PDF 保留同步路径；
- 重试（可配置次数）、取消、并发上限 1–2、排队提示；worker 重启后恢复未完成任务；
- 标准发布改为异步任务，前端显示“解析中/索引中/已发布”；
- 前端标准解析与发布区域显示进度条与失败原因。

**完成标准**：44 页扫描期间 `/health` P95 < 500 ms；两个并发任务按队列执行；失败任务可重试成功；
服务重启后任务不丢；单份 44 页端到端仍 ≤ 3 min。
**不做**：批量报告审核、Excel 批量导出、跨机分布式队列。

### P1-3 WeKnora 运营与评测

**范围**：

- 核查并配置摘要模型；清理重复上传、解析失败与待删除记录；
- 发布幂等：按 `standard_id + version` 去重，重复发布更新同一条 knowledge；
- 权限/审计口径：发布、检索、问答写入审计；知识库权限映射方案先出文档再实现；
- 引用一致性：标准号/条款/页码与 WeKnora 元数据对齐；
- 建 20–30 条标准问答评测集（库内命中、同义改写、库外拒答），记录命中率/拒答率/延迟基线。

**完成标准**：知识库无重复；摘要状态可解释；评测报告可复现；发布/问答审计可查。
**不做**：MCP、多轮会话、租户计费放到后续。

## 7. 验收与风险

**每个增量的完成定义**：

- 代码 + 自动化测试（新增路径必须有回归用例）；
- 部署到目标环境并实测，不只是本地通过；
- 文档记录改动、验证命令、限制与回滚方式；涉及 UI 的补 Before/After 截图；
- 数据迁移类增量必须有对账与回滚演练。

**主要风险与应对**：

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据迁移遗漏/双写不一致 | 业务数据丢失或重复 | 对账 + 双读 + 回滚开关；先小批量再全量 |
| OCR 队列积压 | 扫描高峰排队、体验差 | 并发上限 + 排队提示 + 429；必要时独立 OCR worker/多实例 |
| 客户接口/数据延期 | P1-5 空转 | 先 Excel/CSV 适配层与字段契约；接口到位再替换 |
| 单机资源争抢 | OCR/WeKnora/业务互相拖慢 | 扩容、限流、错峰、监控告警 |
| 范围蔓延 | 增量越做越大、迟迟不能验收 | 以本文“不做”清单为准；变更走评审 |
| “能演示”被当成“已生产” | 验收口径失真 | 每个增量按第 7 节完成定义验收；生产状态以 `/health` 与实测为准 |
