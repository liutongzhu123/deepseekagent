# 报告审核本地数据接入（Phase 1 基线）

> 对应《报告审核专项实施计划 v1.2》阶段 1 工作包 1.3。  
> 目标：在 CRM/任务单/样品系统真实接口到位前，先把客户导出的 Excel/CSV 接进报告审核链路，
> 为“报告—任务单—原始记录—样品—设备台账”的交叉校验提供数据底座。

## 1. 为什么先做这一步

POC 结论：报告审核的确定性规则本身可靠（4 条真实记录 4/4、16 个变异 16/16、干净数据 0 误报），
真正的瓶颈是**数据没有接进来**。没有任务单/原始记录/样品/设备台账，规则 1/2/8/10 只能做报告内自洽检查。
因此第一个开发增量先做“只读、可校验、可替换”的本地数据接入，不碰模型、不碰生产接口。

## 2. 收件目录

客户在本地指定一个 inbox 目录，放入以下四类文件（文件名 = 数据集名，支持 `.csv`、`.xlsx`、`.xlsm`）：

| 数据集 | 推荐文件名 | 也接受 | 主键 | 必填列 |
|---|---|---|---|---|
| 任务单 | `task_orders.csv` | `任务单.csv`、`任务单清单.csv` | `order_no` | 任务单号 |
| 原始记录 | `original_records.csv` | `原始记录.csv`、`记录.csv` | `record_no` | 原始记录编号 |
| 样品 | `samples.csv` | `样品.csv`、`样品清单.csv` | `sample_no` | 样品编号 |
| 设备台账 | `equipment.csv` | `设备.csv`、`设备台账.csv` | `device_id` | 设备编号、溯源有效期 |

第一行是表头；表头按别名匹配（去空格、全角空格、`*`、大小写不敏感）。未识别的列会忽略并给出警告。

## 4. 用法

```bash
cd p0
python scripts/report_inputs_check.py --dir /path/to/inbox
python scripts/report_inputs_check.py --dir /path/to/inbox --json
```

输出四类数据的行数、缺少的必填列、重复主键、跳过行与警告/错误。

退出码：

- `0`：可接入（允许缺文件/重复主键等警告，需业务确认）；
- `1`：目录不存在、文件读取失败或必填列缺失，需修复后再接入。

## 5. 行为边界

- **只读本地文件**：不上传、不调用网络、不写数据库；
- **缺文件是警告**：阶段 0/1 允许先接部分数据；
- **缺必填列是错误**：不会猜测字段；
- **无主键行跳过并计数**：不会静默丢失；
- **重复主键是警告**：同一任务单/样品可能有多条记录，需业务确认口径；
- **不改变现有审核规则**：本增量只提供数据底座，规则接线在下一个增量。

## 6. 接入审核链路

设置环境变量 `P0_REPORT_INPUTS_DIR=/path/to/inbox` 后，报告审核会在 R01–R11 之后追加三条数据驱动检查：

| 规则 | 检查 | 数据来源 |
|---|---|---|
| `X01` | 报告—任务单关键字段一致（报告编号、样品编号、委托单位、样品名称、检验项目） | `task_orders` |
| `X02` | 报告—样品信息一致（样品名称、数量） | `samples` |
| `X03` | 报告—原始记录一致（样品编号、检验日期在报告检验时间内） | `original_records` |

行为：

- 未设置 `P0_REPORT_INPUTS_DIR` 时，行为与旧版完全一致（仍为 11 条规则）；
- 找不到匹配任务单/样品/原始记录，或可比字段均为空/占位（`XX`、`XXXXX`、`----` 等）时，规则为 `skip`，不会误判；
- `X01–X03` 不是管理员可配置的 R01–R11 规则，不受规则配置中心影响；
- 审核结果、历史、批量与 Excel 导出沿用现有结构，`X` 规则会作为普通 findings 出现；
- 新增 `GET /api/v1/reports/inputs/status`（`report:read`）返回四类数据的行数、缺列、重复主键与警告/错误，供后续审核页数据就绪提示使用。
