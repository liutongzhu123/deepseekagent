# 智能客服 S1 合成数据与报价预览契约

本目录是 S1 内部研发夹具，所有组织、标准、项目、证书、排期和价格均为编造的合成值。不得把这里的价格用于客户沟通、合同、生产 CRM 或真实报价；不得将本文件配置为 `P0_CRM_PATH`、`P0_CRM_BASE_PATH` 或生产数据源。

## 文件

- `catalog.json`：合成价格、排期、资质和名称映射数据。各记录使用 `SYN-` 编号并携带 `synthetic` 来源标签。
- `quote-requests.example.json`：供预览接口逐行解析的合成询价输入，内含缺价、过期、已审名称映射和模拟数据源不可用场景。
- `quote-preview.schema.json`：报价预览 API 的 JSON Schema 契约。
- `quote-preview.example.json`：静态预览结构参考，示例金额是纯演示值；工作台接口实际根据询价样例和目录重新匹配，不读取此静态结果。

## 本地预览

本地开发环境设置 `P0_CS_DEMO_ENABLED=1` 并重启服务后，销售或管理员可在报价助手中查看合成 S1 预览；以下两个合成接口默认关闭且要求现有 `quote:parse` 权限：

- `GET /api/v1/customer-service/demo/quote-preview`：逐行匹配内置合成询价样例。
- `POST /api/v1/customer-service/demo/quote-preview/resolve`：接收报价解析字段并匹配合成目录。

“解析已选文件”只调用现有 `/api/v1/quotes/parse` 本地解析接口，再将项目、标准、数量、单位、行号和解析置信度发送给本系统的演示匹配接口；原始文件不会由匹配接口再次接收或转发到外部。此流程不保存解析明细、不使用输入文件中的价格，也不进入现有报价生成、Excel 导出或 CRM 对账。检测项目名称需明确输入并与合成目录一致；真实业务项目或标准通常会显示未命中，这是演示目录隔离的预期结果。生产环境不要开启此开关。

### 当前 CRM 只读适配器预览

`POST /api/v1/customer-service/quote-preview/resolve` 是独立的内部复核入口，同时要求 `quote:parse`、`crm:read` 权限；仅在 `P0_CS_CRM_PREVIEW_ENABLED=1` 且 `P0_CRM_MODE` 为已配置的 `excel`、`csv` 或 `base` 时开放。`off`、预留的 `api` 模式和读取异常均返回不可用，不回退到合成目录。该入口直接读取当前既有 CRM 适配器的只读快照，不代表 CRM API 已接通，也不代表数据经客户验收。

响应使用内容指纹生成 `source_revision` 与行级来源编号，不返回本地文件路径。解析器提取的样品名称参与价格行精确匹配；无精确样品命中时按现有 CRM 对账兼容规则回退匹配，并标记人工确认。CRM 价格行上的 `quantity` 仅作为来源记录数量展示，当前没有被定义为最低起订量，也不用于筛掉价格行。当前适配器没有结构化资质标准/项目范围、名称映射审批状态、价格币种和税口径；这些信息均保持待确认或转人工。此预览不计算汇总、折扣或阈值，不生成客户报价，也不写回 CRM。

当多个有效价格行同时匹配时，接口返回候选样品名、记录单价、来源数量、有效期和来源编号；工作台展示候选用于人工消歧，不会自动选择，也不把候选集合当成已确认报价。

工作台的“记录本次人工选择”调用 `POST /api/v1/customer-service/quote-preview/price-reviews`。服务端重新读取当前 CRM 快照，要求模式和内容版本仍与预览一致，并再次确认所选记录仍属于该行的有效歧义候选；过期预览或伪造/失效候选返回冲突错误。成功后只向现有 append-only 审计记录写入审核人、来源模式/版本、候选记录编号和询价字段指纹，不保存明细、不更新 CRM、不把该选择用于报价。

## 设计约定

- 价格、排期、资质与名称映射独立记录来源、有效期和记录标识；没有来源的事实不得显示为已确认。
- 名称映射必须是明确标记为已审的精确别名；未审或一对多映射按歧义处理。标准编号必须精确匹配，模糊匹配结果不能被转换成已确认报价或标准级资质结论。
- 报价预览保存输入行及来源引用，不在此数据集中预先计算客户应付金额。折扣顺序、税口径、加急费和 10000 元阈值最终以业务签字规则为准。
- 高价示例展示推荐动作，不构成已批准的线上阈值策略。真实系统必须使用版本化规则并记录使用的规则版本。
- 低置信、缺失、过期、服务不可用或来源冲突均以显式状态表示；不得用模型补造业务事实。
- 解析置信度低于现有解析器的 0.85 复核线时，即使目录事实匹配，也要求人工复核。

## 后续开发顺序

1. **已完成本地首版**：服务端默认关闭的预览接口读取固定夹具，明确 `synthetic` 环境和 `demo_only` 标志；工作台逐行显示匹配状态、来源和待补项，并固定提示仅演示。
2. **已接入既有 CRM 只读适配器**：显式开关开启后，仅读取已配置的 Excel/CSV/base 快照；保留内部领域模型、内容版本指纹与行级来源标记。合成与 CRM 来源继续分开。
3. 基于人工批准的规则版本增加确定性决策器；失败场景逐一验证后，才允许在隔离环境读取真实 CRM 数据。
4. 真实报价、委托提交和消息发送使用独立生产适配器，合成夹具不得成为默认回退数据源。

## 当前覆盖的模拟失败场景

| 场景 | 预期表达 |
|---|---|
| 价格未命中 | `missing`，建议补资料或转人工，不输出价格 |
| 价格已过期 | `expired`，不得沿用旧单价 |
| 仅项目级资质 | 可说明项目级范围，不声称标准级认可 |
| 没有排期记录 | `unknown`，不得推测完成周期 |
| 单价较高但规则未批准 | 仍只展示来源，阈值不计算；任何高价拦截策略需业务批准后单独实现 |
| CRM/数据源不可用 | `source_unavailable`，不切换到合成价格伪装真实查询 |
